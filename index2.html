Linux steps in case of emergency😒

Step 1: Find files relevant to forensics and prohibited-media checks

sudo updatedb
locate -i '*.mp3'
find /home -type f \( -iname '*.mp3' -o -iname '*.mp4' -o -iname '*.avi' -o -iname '*.mkv' \) -print

Locate uses an index that may be stale; find searches the directories directly. Inspect results and answer forensics questions before deleting anything. Remove only files the scenario actually prohibits—don’t blindly delete all media.

Step 2: Compare accounts with the authorized-user list

getent passwd
getent group sudo

Compare the results with the README. Some system/service accounts are legitimate, so don’t delete every unfamiliar account or every account with a low UID. Investigate accounts that can log in and aren’t authorized. After confirming an account is unauthorized:

sudo deluser --remove-home USERNAME

This deletes the account’s home directory too; preserve evidence or files needed for forensics first.

Step 3: Check who has administrator privileges

getent group sudo

Remove unauthorized users from the sudo group only after checking the authorized-admin list:

sudo deluser USERNAME sudo

Step 4: Check password status and force a change when required

sudo passwd -S USERNAME
sudo chage -l USERNAME

To require a password change at next login:

sudo passwd -e USERNAME

Set or reset a password interactively with sudo passwd USERNAME; don’t put passwords directly in shell commands.

Step 5: Create a required administrator account

sudo adduser USERNAME
sudo usermod -aG sudo USERNAME
sudo passwd -e USERNAME

Use the exact account name required by the README, set a temporary password interactively, and verify group membership with groups USERNAME.

Step 6: Check UFW

sudo ufw status verbose

If UFW is required, allow required traffic—especially SSH—before enabling it:

sudo ufw allow OpenSSH
sudo ufw enable

Don’t enable a competing firewall if policy names UFW as the approved one. Confirm the required access still works afterward.

Step 7: Keep required services running; remove only prohibited ones

systemctl --type=service --state=running
systemctl is-enabled ssh
systemctl is-active ssh

If SSH is required, don’t stop or purge it. To check whether an unwanted package is installed:

dpkg -l | grep -i PACKAGE

Purge only software prohibited by the README or clearly unnecessary and unauthorized. Review package names before running apt purge.

Step 8: Update from the approved repositories

sudo apt update
apt list --upgradable
sudo apt full-upgrade

Review prompts and preserve required service configurations. Use Update Manager for automatic-update settings if the scenario requires them; enable Source Code sources if the README specifically says to.

Step 9: Disable SSH root login without disabling SSH

Check the effective SSH setting:

sudo sshd -T | grep permitrootlogin

Set PermitRootLogin no in the SSH server configuration, then validate before applying changes:

sudo sshd -t
sudo systemctl reload ssh

Don’t disable password authentication unless the scenario permits it and you have confirmed authorized users can still log in. OpenSSH configuration can include other files, so check the effective setting rather than assuming a line in one file is controlling it.

Step 10: Check the required OS, browser, and display manager

cat /etc/linuxmint/info
apt policy chromium
cat /etc/X11/default-display-manager

Keep the required Mint release and LightDM. Use the approved repository version of Chromium, set it as the default browser if required, and don’t switch display managers.

Step 11: Check automatic login and guest access

Review System Settings → Login Window for automatic login and guest sessions. Disable them if policy requires it; don’t change LightDM itself.

Step 12: Check passwordless sudo rules

sudo grep -RInE 'NOPASSWD|ALL[[:space:]]*=' /etc/sudoers /etc/sudoers.d 2>/dev/null

Investigate unexpected rules. Edit sudo configuration with sudo visudo so syntax is checked.

Step 13: Check for accounts with no password

sudo awk -F: '$2 == "" {print $1}' /etc/shadow

Investigate any results; don’t expose or copy /etc/shadow contents.

Step 14: Check for duplicate user or group IDs

cut -d: -f3 /etc/passwd | sort | uniq -d
cut -d: -f3 /etc/group | sort | uniq -d

Investigate duplicates before making changes; system images can have legitimate exceptions.

Step 15: Look for unexpected listening network ports

sudo ss -tulpn

Identify the owning process and compare it with the required-services list before stopping anything.

Step 16: Check enabled services at startup

systemctl list-unit-files --type=service --state=enabled

Disable only services confirmed unnecessary and unauthorized. Don’t disable SSH or other critical services.

Step 17: Check scheduled tasks

sudo ls -la /etc/cron.d /etc/cron.daily /etc/cron.hourly /etc/cron.weekly
sudo crontab -l

Also inspect users’ crontabs with sudo crontab -u USERNAME -l. Investigate unfamiliar entries before removing them.

Step 18: Review SSH configuration for risky settings

sudo sshd -T | grep -E 'permitrootlogin|permitemptypasswords|passwordauthentication'

Enforce the scenario’s settings, then run sudo sshd -t before reloading the service.

Step 19: Check for unusual startup or login scripts

Review /etc/profile, /etc/profile.d/, /etc/bash.bashrc, and users’ shell startup files for commands you don’t recognize. Don’t delete entries just because they’re unfamiliar; identify what they do first.

Step 20: Check for unexpected package sources

grep -RInE '^[[:space:]]*deb ' /etc/apt/sources.list /etc/apt/sources.list.d 2>/dev/null

Compare sources with the company policy. Don’t remove required official Mint/Ubuntu sources.

Step 21: Review installed packages for prohibited software

apt list --installed

Search specific names with dpkg -l | grep -i NAME. Don’t remove tools or packages required by the OS, README, or forensic questions.

Step 22: Search home folders for suspicious archives and installers

find /home -type f \( -iname '*.deb' -o -iname '*.zip' -o -iname '*.tar.gz' -o -iname '*.tgz' \) -print

These file types aren’t automatically malicious. Inspect contents and context before deleting.

Step 23: Check file permissions on sensitive system files

ls -l /etc/passwd /etc/shadow /etc/sudoers

If permissions appear wrong, research the expected ownership and mode for Mint before changing them.

Step 24: Check for world-writable files in user homes

find /home -xdev -type f -perm -0002 -print

Review each result; some shared files may be intentional.

Step 25: Check for SUID/SGID executables

sudo find / -xdev \( -perm -4000 -o -perm -2000 \) -type f -print 2>/dev/null

Compare unexpected results with the installed packages. Don’t remove permission bits indiscriminately; system programs may need them.

Step 26: Check for unexpected user login shells

getent passwd | awk -F: '$7 !~ /(nologin|false)$/ {print $1, $7}'

Compare login-capable accounts with the authorized list, accounting for legitimate system accounts.

Step 27: Check the system clock and time synchronization

timedatectl status

Correct time helps logs and updates work properly. Don’t change network or time settings if the competition environment requires a specific setup.

Step 28: Review recent authentication and system events

sudo journalctl -p warning..alert -b
sudo journalctl -u ssh -b

Look for suspicious activity, but preserve logs if they may be needed for forensics.

Step 29: Check disk space and failed services

df -h
systemctl --failed

Resolve problems without removing required files or services.

Step 30: Recheck the requirements after changes

sudo ufw status verbose
systemctl is-active ssh
systemctl is-enabled ssh
cat /etc/X11/default-display-manager
